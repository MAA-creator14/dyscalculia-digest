### Full MVP scope (Flows A–G, for reference)

This PRD covers **Flow G only** — the rest are already shipped and are included here so this document is a complete, standalone picture of where Share fits, rather than requiring a reader to cross-reference PLAN.md.

**First-run intake:** On first use, a single open, qualitative question — *"how would you describe your relationship with numbers?"* — is asked and stored for the founder's own learning. It doesn't configure product behavior yet; it's a listening exercise for future personalization.

**Flow A — Ingest & Restate:** User pastes a table, uploads a CSV, uploads/pastes a screenshot of a dashboard, or connects a read-only Google Sheet. Screenshot input runs a vision-model extraction shown back as an editable preview the user must explicitly confirm before anything is computed (a misread digit from an image is the single highest-risk failure mode in the product). A deterministic engine parses typed columns and computes totals, deltas, rank/comparison, and cautious/under-flagged rule-based anomalies — assuming UK/US number formats for MVP, and failing loudly with a specific explanation rather than silently guessing when a column can't be confidently interpreted. Output renders each key number as a **NumberCard**: numeral + plain-language sentence at equal visual weight, icon+color+word for direction, comparative framing, optional sparkline/bar. Anomalies surface separately in a "Worth a second look" panel.

**Flow B — Exec summary:** A synthesized headline takeaway, 2–3 largest movers, multi-period trend/streak, most severe anomaly, comparison to a prior period/target, and a data-quality caveat when relevant — all above the NumberCard stream. `lib/compute/summarize.ts` deterministically selects/ranks what's noteworthy; the LLM only phrases that selection into sentences, never decides importance from raw numbers itself. Includes a "listen" control (Flow F) and a "copy as text" action.

**Flow C — Ask a follow-up question:** A chat input under the restated table answers dataset-specific questions via tool calls returning precomputed values only (never recomputed/invented), and may also explain general data-literacy concepts using general knowledge, visibly distinguished from dataset-specific figures.

**Flow D — Inline calculator:** Anywhere a user might need to mentally compare two numbers, the UI shows the computed answer inline; a persistent small calculator widget covers ad hoc comparisons.

**Flow E — Session recall:** A recent-interpretations list (computed summaries only, never raw source data) so users can return without re-uploading.

**Flow F — Hear it out loud:** Every NumberCard, the exec summary, and the anomaly panel get a "listen" control sending the already-guardrailed narration sentence (never raw numbers) to a TTS provider (ElevenLabs) for playback. Because TTS only ever speaks pre-validated text, it can't introduce a new/wrong number. Audio is cached by a hash of the narration text so repeat plays don't re-hit the API.

**Flow G — Share (this PRD):** A "share" action generates a read-only link to one interpretation — now extended, per this session's Discover stage, to also carry the PM's own commentary/recommendation alongside the computed summary — that a colleague can open without an account. Simple, always-valid, hard-to-guess link with a manual revoke action; no automatic expiry for MVP.

## Problem
A PM has used Flow A–D to get a restated, trustworthy interpretation of a dataset. They now need to hand that interpretation to a colleague or stakeholder (e.g. their manager, in an exec update) — but forwarding the raw restated view only conveys *what the data says*, not *what the PM thinks should happen next*. Screen-sharing or "copy as text" (Flow B) loses the NumberCards/redundant coding that make the view trustworthy in the first place, and neither lets the PM add their own framing.

## Evidence
- ✅ **Validated:** PLAN.md documents the underlying pain (numeric misreads are professionally risky for this persona) from the founder's own lived experience.
- ⚠️ **Assumed:** That PMs specifically want to *annotate* a shared view rather than just forward it as-is — this came from this session's Discover-stage correction, not from user research. **This is the single biggest assumption in this PRD** and is called out again in Open Questions.
- ⚠️ **Assumed:** A read-only link (vs. e.g. exporting a PDF/image) is the right sharing mechanism — inherited from PLAN.md's existing Flow G scoping, not re-litigated here.

## Proposed Solution

### How It Works
1. On the interpretation page (Flow A/B output), a "Share" action opens a share-setup panel with a plain-text commentary field (placeholder: *"Add your take — what should the reader do with this?"*), optional and empty by default.
2. Creating the share generates a hard-to-guess, always-valid token; `POST /api/share` stores `{ interpretationSummary (computed only), commentary, createdAt, revoked: false }` keyed by token — never the raw source table.
3. `app/(app)/share/[token]/page.tsx` renders the computed interpretation (NumberCards, exec summary, anomalies — same components as the authenticated view) plus the PM's commentary in a clearly distinct, visually separate block (so a reader never confuses "what the data says" with "what the PM thinks") — no login required to view.
4. The PM can revoke the link at any time (`DELETE /api/share` or a revoke action on their own interpretation page); a revoked token renders a plain "this link has been revoked" page, not a 404 (a 404 would leak whether a token ever existed).
5. Commentary is editable after creation (the PM's thinking may evolve) up until revocation; editing does not require a new token.

### User Stories

**Story 1:**
- **As a** PM who just reviewed a metrics drop
- **I want to** add a short note explaining why I think it happened before sharing
- **So that** my manager sees my judgment alongside the numbers, not just the numbers alone

**Story 2:**
- **As a** PM sharing a link in a Slack DM
- **I want to** the recipient to open it with zero signup
- **So that** I don't create friction for someone I'm just trying to keep informed

**Story 3:**
- **As a** PM who shared a link and later realized the analysis was wrong
- **I want to** revoke it instantly
- **So that** an outdated or incorrect view stops being accessible without me having to chase the recipient down

## Evals (golden dataset)

Flow G has no generative output of its own — the commentary is PM-authored plain text and the summary was already narrated upstream by Flow A/B. So this isn't an LLM-quality eval (grading phrasing/tone); it's a **data-boundary regression suite**: every share-record shape the product can produce, checked against a fixed set of assertions so a future change can't silently leak raw data or break revoke semantics.

**Golden dataset:** a small, fixed set of fixture interpretation records covering the meaningfully different shapes the product produces, stored under `lib/share/__fixtures__/`:
1. Paste-table source, no anomalies, no commentary
2. CSV source, with anomalies flagged, with commentary
3. Screenshot/vision-extracted source (the highest-risk input path per Flow A), with commentary
4. Google Sheets source, long multi-paragraph commentary (edge case from Story 1)
5. A record with commentary containing only whitespace (must render as "no commentary," per Story 1 AC1)

**Assertions run against every fixture's share payload:**
- The serialized payload's keys are exactly the defined summary fields (numbers, labels, anomaly flags, commentary) — never the source table, source file name, or any raw cell value. This is the single most important assertion in the PRD, since it's the product's core privacy commitment.
- Commentary (when present) is a distinct field, never concatenated into or mistakable for a computed sentence.
- A revoked-token fixture and a never-issued-token fixture produce byte-identical (or near-identical, per Story 3 AC2) responses.

**Where these live:** `app/api/share/route.test.ts`, run in CI alongside the existing `lib/compute/*.test.ts` suite (this project already unit-tests its deterministic layer the same way — see `lib/compute/anomalies.test.ts` etc. — so this follows an established pattern rather than introducing a new one).

## Non-Goals
- No automatic link expiry (matches existing PLAN.md decision for MVP).
- No per-viewer access control, view tracking/analytics, or "who viewed this" — out of scope for MVP.
- No rich text/formatting in commentary — plain text only, to keep the guardrail (LLM never touches this field) simple and the scope small.
- No commenting/reply *from* the viewer — this is one-way, PM-to-reader.
- Not re-litigating whether a link is the right mechanism (vs. PDF/export) — inherited as fixed scope from PLAN.md.

## Dependencies

### Feature Dependencies
- **Flow A/B (Ingest & Restate, Exec Summary)**: must exist to have a computed interpretation to share — already built.
- **Persistent storage for share records**: the product currently has no database (per PLAN.md, no auth/accounts yet in MVP) — this is the first feature that needs *any* server-side persistence. **This is the critical dependency.**

### Team Dependencies
- None — solo project.

### External Dependencies
- None beyond whatever storage choice is made (see below) — no third-party API required.

**Critical Path:** Standing up minimal persistence (even a simple KV/Postgres table) is the blocking dependency — everything else in this PRD is straightforward once a token can be durably stored and looked up.

## Risks
| Risk | Type | Impact | Mitigation |
|------|------|--------|------------|
| PM commentary field goes unused (nice-to-have, not a real want) | V | M | Dogfood first (leading indicator above) before investing further (e.g. rich formatting) |
| Guessable/enumerable tokens expose another user's shared interpretation | U | H | Use a cryptographically random token (not sequential IDs); no directory listing endpoint |
| Adding "first real persistence" scope-creeps into a bigger infra project | F | M | Pick the smallest viable store (e.g. a single table) — do not use this feature as an excuse to build out a full data layer |
| Revoked-link page accidentally leaks that a token *did* exist to a snooping third party | U | L | Revoked and never-existed should render identically or near-identically |
